# 项目协作与文档维护规则

## 项目定位

本工作区用于交接 IMU 传播/预积分的验证代码：在一致的输入、噪声和误差定义下，提取各实现的协方差、bias Jacobian，并与对应的 GTSAM 参考模型核对。完整 SLAM/VIO 轨迹评测不是目前已完成的验证范围。

先阅读根目录 `PROJECT_HANDOVER.md`，再阅读对应仓库 `imu_data` 下的当前 README。此工作区包含多个独立 Git 仓库；根目录不是 Git 仓库。根总览及规则需同步到中心仓库的 `PROJECT_HANDOVER.md`、`handover/WORKSPACE_AGENTS.md`，用于在线交接；跨仓库链接需改为 GitHub 链接，中心仓库内链接用相对路径。

## 过时文档规则

1. 对本项目自写、且接口、实验结论或流程已不适用的文档，重命名为 `OUTDATED_<原文件名>`。统一使用大写 `OUTDATED_`，已带此前缀的文件不要重复添加。
2. 保留历史正文和原始 PASS/FAIL，不删除失败证据；在顶部添加归档日期、过时原因、替代文档链接。旧需求原文仍可用于追溯，标记过时不等于取消该需求。
3. 若只有局部补充且主体仍准确，直接更新当前文档；不要把所有旧日期文档一律标为过时。上游/第三方 README、许可证、原始数据及日志不得因年代久而批量改名。
4. 重命名后更新当前文档的引用，保留清晰的当前阅读入口；历史正文里的旧工具名作为历史内容保留。
5. 结果发生实质变化时，同步更新 `PROJECT_HANDOVER.md` 和对应仓库的当前说明，注明本地修改是否已提交、推送。

## 实验结论与交接规则

- 每种方法说明：文件职责、实际实验、输入/参考模型、阈值、结果证据、需求覆盖、GitHub 链接及版本状态。
- 区分“有代码”“已编译”“旧结果重新比较”“从源码重新导出”“已通过”“未复核”；未复核不等于失败，也不能写成通过。
- 区分原生核心结果、坐标转换、核心修复和仅导出层替换。有限差分核验不能冒充内部解析结果；不得为获得 PASS 而偷偷放宽阈值或修改参考答案。
- 说明具体检查项。当前跨库比较器不检查 `J_s/J_e`；仅有 `Sigma_z/JincBias` 通过，不能写成所有因子 Jacobian 均已验收。
- ORB 使用 9D 预积分及独立 bias random walk 模型；不可不加说明地与 Combined 15D 协方差混比。
- OKVIS/IMU preint 的研究程序与 GTSAM 基准生成器不等于各自完整系统已全面通过。复用老师/上游文件时标明来源，不把已有核心全部算成我们新增。
- 本地测试通过不代表 GitHub 已包含最新代码。提交、推送仍按用户授权范围执行。
